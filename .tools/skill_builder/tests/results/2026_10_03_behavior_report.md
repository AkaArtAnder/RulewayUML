# Отчёт о прогоне оставшихся тестов скилла RulewayUML

Дата: 2026-10-03.

Проверяемая редакция: временная сборка `rulewayuml 0.1.2-dev` из текущих исходников проекта. Сборка и рендеринг выполнялись в Docker без сети на PlantUML `1.2025.10` с лимитом `4096`. Исходный пакет и поведение скилла во время проверки не менялись.

## Объём проверки

Выполнены пять ранее подготовленных поведенческих случаев:

1. восстановление полного маршрута по нехронологичным артефактам;
2. построение черновика по неполным и противоречивым артефактам;
3. двухэтапная разработка регламента с нуля;
4. локальная правка SLA с инверсией смысла вопроса цикла;
5. вставка действия с сохранением постоянных ID.

Для каждого случая выполнен один прогон со скиллом и один контрольный прогон без него. Результаты проверены независимыми оценщиками по восьми утверждениям на случай. Дополнительно выполнены полный технический тест пакета, проверка контракта экспортёра, стандартная структурная валидация, точное сравнение редактируемых копий и визуальная проверка изображений.

## Поведенческие результаты

| Случай | Со скиллом | Без скилла | Наблюдение |
| --- | ---: | ---: | --- |
| Полные артефакты | 8/8 | 8/8 | Оба варианта восстановили запуск, цикл, решение и завершение без вымышленных правил. |
| Неполные артефакты | 8/8 | 8/8 | Архивирование осталось отдельным фрагментом; конфликт ответственности не разрешён молча. |
| Разработка с нуля | 8/8 | 7/8 | Контроль до получения учебных ответов дословно использовал позднее заданную структуру итогового текста. |
| Инверсия условия | 8/8 | 8/8 | В обоих вариантах изменены только SLA и вопрос; `нет` возвращает в цикл, `да` ведёт к согласованию. |
| Постоянные ID | 8/8 | 8/8 | `РСЗ-05` добавлен после цикла перед `РСЗ-03`; прежние ID и поля сохранены. |
| **Итого** | **40/40 (100%)** | **39/40 (97,5%)** | Разница образована одним критерием одного случая. |

Вывод ограничен одним запуском каждой конфигурации. Повторяемость и дисперсия одного и того же случая не измерялись. В 39 из 40 попарных критериев обе конфигурации дали одинаковый формальный результат, поэтому текущий набор лучше подтверждает работоспособность, чем величину преимущества скилла.

## Технические результаты

- Полный `.tools/skill_builder/tests/check.py` пройден: пакет самодостаточен, контрольные суммы совпадают, экспортированы 9 схем, сохранены кириллица, специальные символы, SVG-знак, SLA и ссылки.
- На дату прогона содержимое свежей временной сборки побайтно совпало с распакованным архивом под внутренним обозначением `0.1.2-dev`; различался только бинарный ZIP из-за служебных метаданных упаковки. Позднее та же функциональная редакция выпущена как `0.0.1` без суффикса; её повторная структурная проверка зафиксирована в контексте задачи.
- Portable PUML отрисован без каталога компонентов; текст совпал с обычным экспортом.
- Повторный экспорт перенесённого комплекта прошёл; существующий результат не перезаписывается, ошибки не оставляют частичный комплект.
- Растровые вставки и несовместимые теги выравнивания для Wiki корректно отклоняются.
- `.tools/skill_builder/tests/check_export_contract.py` пройден с подставленным движком: проверены единый CLI, состав файлов, перенос зависимостей, ссылки HTML, версия и очистка после отказа.
- `quick_validate.py` сначала не запустился в базовом образе из-за отсутствия его внешней зависимости `PyYAML`. Повторный запуск выполнен в том же контейнере без сети с read-only подключением уже установленного `PyYAML`; результат — `Skill is valid!`. Зависимости на хост не устанавливались.
- `evals.json`, все `eval_metadata.json` и `grading.json` валидны; `git diff --check` проходит.
- Публичные `examples/` и `components/` поведенческими тестами не изменены.

Визуально проверены схемы полного маршрута, обоих фрагментов неполного случая и результаты остальных сценариев: текст читается, обрезаний и наложений не обнаружено. В схеме полного маршрута подпись возврата расположена плотно у линии, но остаётся читаемой.

## Обнаруженные ограничения методики

1. У контрольного результата сценария инверсии обычный редактируемый PUML содержит `!include ../components/...`, но соответствующий каталог зависимостей в его выдаче отсутствует. Portable PUML работоспособен. Текущие восемь критериев этот разрыв не измеряют; комплект со скиллом содержит редактируемую структуру с компонентами.
2. Двухэтапный сценарий с нуля был смоделирован в одном задании через два файла. Для строгой изоляции первый ответ в следующем benchmark следует получать отдельным ходом до передачи учебных ответов.
3. Среда координации не передала достоверные длительность и число токенов по каждому исполнителю. Поле `tokens` агрегатора содержит неполный прокси по символам выходов и не является измерением токенов; сравнение времени и расхода ресурсов исключено из выводов.
4. Реальная кликабельность внутри Яндекс Wiki не проверялась: локально проверены ссылки SVG/HTML и совместимость экспортируемого кода, но не поведение авторизованной Wiki.
5. Переносимость в других агентных системах не проверялась. Прогон выполнен только в текущей среде Codex; контроль без скилла не заменяет тест другого агента.
6. Учебные сценарии подтверждены, но критерий по одному реальному пользовательскому случаю для режимов разработки с нуля и редактирования остаётся отдельной приёмочной проверкой.

## Итог

В текущей среде локальные технические тесты и все пять подготовленных поведенческих случаев пройдены. По результатам этого прогона блокирующих дефектов в поведении скилла не обнаружено, поэтому его исходники не менялись.

До заявления полной готовности первой версии остаются внешние проверки: реальные пользовательские случаи двух режимов, кликабельность в Яндекс Wiki и переносимость хотя бы в одной другой агентной системе. Для следующего benchmark полезно добавить критерий самодостаточности редактируемого комплекта, разделить первый и второй ходы сценария с нуля и выполнить несколько повторов.

После проверки сырые каталоги прогонов, экспортированные изображения и статический просмотрщик удалены по решению владельца. Для повторения сохранены:

- `../evals/evals.json` и `../evals/files/` — задания, критерии и исходный пользовательский материал;
- `2026_10_03_benchmark.md` — компактная формальная сводка;
- `2026_10_03_analysis_notes.json` — аналитические наблюдения;
- этот отчёт и контекст задачи — условия запуска, результаты и ограничения.
