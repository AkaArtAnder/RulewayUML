# Регламенты RulewayUML

Помоги пользователю получить понятный регламент и соответствующую ему схему деятельности. Работай с файлами и локальным рендерером средствами доступной агентной системы; специальные инструменты Codex не требуются.

## Выбери режим по запросу

- **Готовый регламент:** прочитай фактическое содержание, сохрани термины и правила автора. Восстанови порядок по зависимостям и переходам, а не по расположению разделов. Связывай существенные элементы схемы с фрагментами источника.
- **Разработка с нуля:** помоги определить границы, роли, действия и результаты, затем альтернативы и повторы. Запиши итоговый текст в формате пользователя и подготовь схему из той же версии содержания.
- **Редактирование:** работай от существующего `.puml`, сохрани его библиотеку, ID, адреса и незатронутые правила. Учитывай связанные изменения оснований и переходов. Не переписывай весь регламент ради локальной правки.

Подробности разбора и уточнений — в [references/methodology.md](references/methodology.md). Читай этот справочник при построении или изменении логики процесса.

## Обязательные правила

- Каждое действие оформляй через `$ruleway_action`. Обязательны ID, название, ответственная роль и результат; инструкция, срок/SLA и ссылка на подрегламент независимы и необязательны.
- ID постоянен: кириллическая `Р`, два символа выбранной аббревиатуры, дефис и две цифры. Новое действие получает свободный номер; существующие не перенумеровываются. Очередность задают только переходы.
- Используй явные стандартные `if`, `repeat`, `fork`, `start`, `stop`. Не скрывай логику за дополнительными обёртками. Условия и границы оформляй публичными функциями библиотеки.
- Не придумывай ответственность, сроки, результаты, критерии отказа и лимиты повторов. Уточняй только пробелы, влияющие на смысл; известные части можно подготовить параллельно. Не требуй заполнения необязательных полей.
- Ссылки заполняет пользователь. Сохраняй адреса; отсутствие ссылки не блокирует работу. Не подбирай цели, не проверяй доступность ресурсов или права читателей. При технической проверке используй учебные ссылки.
- Отделяй предложения и открытые вопросы от правил пользователя. Если существенные вопросы остались, назови результат черновиком. При достаточных данных не вводи дополнительную обязательную приёмку перед генерацией.

Точный API и переносы строк — в [references/components.md](references/components.md); прочитай перед формированием кода. Образцы с полным и частичным заполнением параметров доступны через [references/routes.md](references/routes.md). Учебные сроки и исходы из них не являются правилами по умолчанию.

## Подготовь и выдай результат

1. Для новой схемы скопируй весь [assets/components/](assets/components/) в рабочий каталог пользователя. Для существующей схемы сохрани её совместимые зависимости; не заменяй их без причины.
2. Сверь доступность оснований на каждом пути, подписи исходов, возвраты и завершения. При инверсии вопроса условия проверь оба перехода. Успешное отображение не доказывает смысловую корректность.
3. Выполни экспорт по [references/export.md](references/export.md): редактируемый исходник с зависимостями, SVG, HTML для просмотра и развёрнутый `*_portable.puml` для вставки в Wiki. Для Wiki и браузера используй одну сборку на PlantUML `1.2025.10`; отдельные профили и повторный экспорт для другой среды не нужны. Все файлы должны соответствовать одной редакции. Пользовательские материалы добавляй только из предоставленных файлов.
4. Оцени читаемость изображения и техническую работу ссылок в заявленной среде либо явно передай визуальную проверку пользователю, если просмотр недоступен. Не сообщай о проверках, которых не выполнял.
5. Выдай ссылки на файлы, кратко назови изменения и оставшиеся вопросы. При разработке с нуля добавь итоговый текст. Если экспорт недоступен или завершился ошибкой, сохрани исходник и сообщи, что новый SVG не получен.

Версия и лимит берутся из [assets/runtime/Dockerfile](assets/runtime/Dockerfile), скопированного из окружения проекта при сборке скилла. Оформление проверено пользователем на PlantUML `1.2025.10`; это не подтверждает работу ссылок в Wiki или произвольной схемы. Подготовка файлов не включает их публикацию, загрузку на Wiki или выбор хостинга. Схема описывает процесс, но не исполняет его и не отслеживает сроки.
