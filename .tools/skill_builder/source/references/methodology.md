# Методика работы с регламентом

## Разбор и уточнения

Собери компактное рабочее описание: назначение, событие начала, доступные входы, роли, действия с результатами, переходы и допустимые исходы. Это инструмент анализа, а не обязательный новый формат документа.

В готовом регламенте сохраняй связь с пунктами источника. При разработке с нуля начни с основного пути и дополни альтернативами. В режиме редактирования сначала установи область изменения и связанные зависимости; не пересоздавай процесс целиком. Если дан только SVG, запроси исходник для точного редактирования; реконструкцию по картинке обозначай отдельно, она не гарантирует сохранения исходных данных.

Приоритет уточнений:

| Пробел | Действие агента |
| --- | --- |
| Неясно, кто выполняет работу или что считается результатом | Уточнить до окончательного оформления этого действия |
| Неясны запуск, исход ветви, возврат или завершение | Показать конкретную неопределённость и спросить о правиле |
| Противоречивые правила в источнике | Привести фрагменты и объяснить различие маршрутов; не выбирать молча |
| Не указан необязательный срок, инструкция или ссылка | Оставить поле пустым, если оно не требуется смыслом процесса |
| Срок задан, но неизвестны значимые единица времени или точка отсчёта | Уточнить их; не подставлять учебный норматив |
| Не выбраны название/аббревиатура нового регламента | Предложить понятное обозначение, явно отделив его от предметных правил |

Группируй связанные вопросы; продолжай работу с определёнными частями. При отсутствии ответа не считай предложенный вариант согласованным. Изменение предпочтения пользователя действует и при последующих правках.

## Выделение действий

Одно действие передаёт понятную работу одной ответственной роли и наблюдаемый результат. Смена роли, передача самостоятельного результата или развилка помогают определить границу действия. Несколько пунктов проверки одной ролью могут остаться чек-листом.

Название формулируй глаголом: «Проверить комплект». Результат описывает итог: «Замечания зафиксированы». Не создавай новый обязательный документ, если источник требует только состояния или решения. Входы действия учитывай для зависимостей; отдельного аргумента входов в API нет.

Сохраняй понятия и названия автора. Инструкцию заполняй конкретными операциями из источника, SLA — заданным нормативом и точкой отсчёта. Срок не создаёт автоматически маршрут при просрочке. Дочерний регламент раскрывает работу; переход по ссылке не является запуском или возвратом процесса.

## Очередность и маршруты

1. Установи, какие данные есть при запуске и какие создаются действиями. Для каждого шага найди источник необходимых данных.
2. Построй основной путь по зависимостям. Номер ID, соседство разделов и расположение блоков не доказывают очередность.
3. Для каждой развилки укажи вопрос, доступное основание и подписанные исходы. Проверку выполняет предшествующее действие с ответственным. Отсутствие основания или ответа не означает отрицательный ответ.
4. Для цикла задай причину возврата, точку доработки и выход по последней проверке. Если установлен предел повторов, покажи путь при его достижении. Самостоятельно предел не добавляй.
5. Параллельность выбирай по независимости работы, а не по различию ролей. Определи, каких результатов ждёт продолжение. Неполученный обязательный результат не считай готовым.
6. Для внешнего ожидания установи событие продолжения. Срок и путь при неполучении ответа добавляй, только если соответствующее правило задано.
7. Для дочернего процесса свяжи входы, возвращаемые результаты и продолжение основного. Замечания могут означать выполненную проверку и доработку; невозможность проверки — другой результат.
8. Подпиши запуск и каждый предусмотренный конец. Доработка не является завершением; конец дочерней проверки не обязательно заканчивает основной процесс.

Дорожки используй по пользе для чтения; ответственный остаётся в каждом действии. Не меняй общий стиль и марку ради отдельной схемы.

## Постоянные ID при правке

Сохраняй ID при переименовании, перемещении и повторном выполнении узла. Вставка и удаление не перенумеровывают остальные действия. Новый шаг между `РСЗ-01` и `РСЗ-02` может получить `РСЗ-05`; размещение определяется переходами.

Для нового действия выбери свободный двузначный номер; обычно удобно взять следующий после наибольшего известного. Не присваивай новой работе ID, про который известно, что он принадлежал удалённому действию. Не обещай проверку всей истории, если её не предоставили. Если свободных номеров в принятом формате нет, сообщи об ограничении и обсуди разбиение процесса, не расширяй формат самостоятельно.

Условия, начало и завершение не получают ID действий. Дочерний регламент имеет собственную аббревиатуру. После удаления или разделения действия актуализируй ссылки на его результаты; сохрани не затронутые запросом адреса и поля.

## Готовность содержания

Пройди основной путь, каждую альтернативу и один повтор. По применимости проверь неуспех дочернего процесса, неполученный параллельный результат и достижение заданного лимита. На каждом пути должны быть доступны основания и понятны ответственность, результат и продолжение.

После правки сравни версии: изменилась только запрошенная область и необходимая связанная логика. При инверсии вопроса «Есть замечания?» → «Заключение без замечаний?» поменяй соответствие ответов маршрутам, сохраняя доработку при замечаниях. Итоговый текст и SVG должны относиться к новой редакции.
