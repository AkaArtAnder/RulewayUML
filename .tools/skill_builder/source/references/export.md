# Экспорт и размещение

## Среда

Нужны Bash и Docker на компьютере либо уже открытый Dev Container. Для Wiki и браузера используется одно окружение: PlantUML `1.2025.10`, Java 17 / Debian Bookworm, DejaVu Sans, Graphviz и Python 3 со стандартной библиотекой. Дополнительных Python-пакетов экспортёр не требует. Версия PlantUML и лимит 4096 читаются из [assets/runtime/Dockerfile](../assets/runtime/Dockerfile), включённого в пакет из проекта. Зависимости на хост не устанавливаются.

Если образ ещё не собран, из каталога установленного скилла:

```bash
docker build --tag rulewayuml-dev:plantuml-1.2025.10 --file assets/runtime/Dockerfile assets/runtime
```

Для сборки нужен доступ к источникам базового образа и PlantUML. Экспорт через Docker затем выполняется без сети. Если Docker недоступен, подготовь исходник и объясни, что SVG пока не создан. Не отправляй пользовательский регламент на внешний сервер рендеринга вместо локального запуска.

## Рабочий каталог

Для новой схемы достаточно структуры:

```text
work/
  components/        Полная копия assets/components/ из пакета
  regulation.puml    Подключает components/action.puml и нужные модули
  materials/         Только предоставленные пользователем материалы, если есть
```

При редактировании сохрани структуру исходного проекта. Передавай в экспорт каталог, относительно которого доступны `components/` и исходники. Например, у пакета таким корнем является `assets/`, а исходники расположены в `examples/`. Локальные подключения должны работать из переносимой копии; абсолютные пути к исходному компьютеру непереносимы.

## Команда

Из каталога скилла:

```bash
bash scripts/export.sh /путь/к/work /путь/к/новому_результату regulation.puml
```

Пара связанных схем из пакета:

```bash
bash scripts/export.sh "$PWD/assets" /tmp/ruleway_review_export \
  examples/subregulation_result.puml examples/subregulation_review.puml
```

Локальные материалы явно добавляются опцией `--asset`:

```bash
bash scripts/export.sh /путь/к/work /путь/к/новому_результату \
  regulation.puml --asset materials
```

Файлы `.puml` и пути `--asset` задаются относительно рабочего каталога. Путь может содержать пробелы и кириллицу; заключай его в кавычки. `..`, внешние символьные ссылки и ссылки на каталоги не поддерживаются. В одном файле должна быть одна самостоятельная схема. Экспортируются только перечисленные схемы, полный `components/` и явно переданные материалы. Дополнительные локальные включения можно передать через `--asset`; сторонние сетевые включения не поддерживаются автономным комплектом.

Используется образ `rulewayuml-dev:plantuml-1.2025.10`; имя образуется из версии в Dockerfile. Выбирать профиль или запускать экспорт ещё раз для Wiki не нужно. Для другого имени локального образа с тем же окружением передай `RULEWAY_IMAGE=имя_образа`; скрипт всё равно проверит версию PlantUML. В Dev Container используется окружение текущего контейнера; несовпадение версии вызывает ошибку. Старый контейнер после обновления Dockerfile следует пересобрать.

Каталог результата должен быть новым. При ошибке весь незавершённый комплект удаляется, прежние результаты и исходники остаются на месте. Это позволяет сохранять редакции отдельно. Не выдавай прежний SVG за новое изображение при неудаче. Для повторного экспорта выбери другой каталог; затем пользователь может заменить опубликованную редакцию.

## Что выдаётся

```text
result/
  source/                      Редактируемые исходники и их зависимости
    components/
    regulation.puml
  diagrams/
    regulation.svg             Результат PlantUML
    regulation.html            Просмотр SVG как отдельного документа через object
    regulation_portable.puml   Развёрнутый код без локальных !include
  export_manifest.json         Версия PlantUML, лимит, пути и хеши исходников
```

Файл `regulation_portable.puml` служит единым кодом для вставки, в том числе в Wiki. Относительные подкаталоги сохраняются: для `examples/review.puml` результат будет в `diagrams/examples/`. Локальные материалы копируются в `source/` и `diagrams/` с теми же относительными путями. Экспортёр не переписывает URL: относительные ссылки разрешаются от места конкретного SVG. Передавай связанные схемы вместе, если они должны входить в комплект; отсутствие ресурса по ссылке не является ошибкой экспорта.

Редактировать следует файлы в `source/`: они сохраняют вызовы RulewayUML. В `_portable.puml` действия уже развёрнуты в стандартный PlantUML, локальные включения не нужны. Не используй его вместо редактируемого оригинала при следующей правке. После изменения оригинала экспортируй заново.

## HTML, SVG и Яндекс Wiki

HTML размещает SVG через `<object>` и даёт ссылку для отдельного открытия. SVG остаётся документом со своими ссылками. Для проверки обслуживай весь комплект через локальный HTTP, чтобы переходы к соседним файлам работали так же, как после размещения. Ограничения открытия локальных файлов зависят от браузера. Встраивание SVG как обычного `<img>` показывает изображение, но не предоставляет его внутренние кликабельные области.

Пример локального просмотра из каталога результата при уже доступном Python 3:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Открывается адрес `http://127.0.0.1:8000/diagrams/regulation.html`; для другого расположения используй соответствующий путь. Установка Python на компьютер не нужна для экспорта; при его отсутствии можно использовать HTTP-сервер из контейнера или доступную функцию предпросмотра агента.

В Яндекс Wiki доступны разные представления, совместимость нужно проверять на выбранной странице:

- SVG как изображение — для отображения, с возможностью отдельного открытия оригинала, если Wiki её предоставляет.
- Развёрнутый `_portable.puml` — код для блока PlantUML. Копируй всё содержимое, включая `@startuml` / `@enduml`, стили и определение знака. Обрамление блока добавляется средствами редактора Wiki, не внутрь `.puml`. На стороне Wiki локальные компоненты и Docker не нужны. Условие и векторный знак основной демосхемы подтверждены пользователем на движке `1.2025.10`; произвольный синтаксис и кликабельность проверяются отдельно.
- HTML/SVG как отдельная страница — для переходов внутри схемы. Её встраивание фреймом зависит от настроек Wiki и сервера; размещение и публикация требуют запроса пользователя.

Проверка локального SVG или HTML не подтверждает поддержку Wiki. Не изменяй страницу пользователя ради проверки без поручения. Для технического клика используй учебный адрес; доступность и права на реальные цели ссылок не проверяй.

В SVG текст, геометрия и фирменный знак векторные; знак имеет исходный размер 48 × 48, градиент приближён цветными контурами. Оцени читаемость при целевой ширине. Если схема слишком велика, предложи обзор с дочерними схемами, сохраняя логику.

Для совместимости используй библиотечный векторный знак из контуров. При работе со старой копией компонентов сохрани пользовательские изменения и обнови PNG-знак и теги `<center>`/`<left>` до текущей реализации. Экспортёр отклоняет растровые вставки и буквальные теги выравнивания без выдачи частичного комплекта. Проверенное локальное окружение использует Graphviz `2.43.0`; оно не воспроизводит всю инфраструктуру сервиса Wiki с Graphviz `14.0.1`.

Источники по способам отображения: [SVG в PlantUML](https://plantuml.com/svg), [SVG как изображение](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image), [диаграммы Wiki](https://yandex.ru/support/wiki/ru/wysiwyg/diagrams), [изображения Wiki](https://yandex.ru/support/wiki/ru/wysiwyg/images), [фреймы Wiki](https://yandex.ru/support/wiki/ru/wysiwyg/embed-content).
