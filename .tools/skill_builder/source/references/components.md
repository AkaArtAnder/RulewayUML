# API компонентов

Все аргументы — строки. Подключаемые файлы находятся в `assets/components/`; переносится весь каталог, включая `assets/ruleway_logo.iuml` и `boundary_label.iuml`. Публичные компоненты подключают общий стиль автоматически.

## Действие

```plantuml
$ruleway_action($id, $name, $responsible, $result, $instruction = "", $sla = "", $subregulation = "")
```

Первые четыре поля обязательны. ID: кириллическая `Р` + два символа аббревиатуры + дефис + две цифры. Он постоянен, а не порядковый номер выполнения. Имя — работа, ответственный — роль, результат — наблюдаемый итог и/или ссылка на шаблон. Последние три поля независимы; `""` скрывает поле. Для SLA укажи длительность с точкой отсчёта или событие окончания. Ссылки имеют вид `[[адрес Название]]`; их адреса предоставляет пользователь.

Полное заполнение показано в `РПВ-01` [параллельного образца](../assets/examples/parallel_results.puml) и `РПМ-02` [основного процесса](../assets/examples/subregulation_result.puml). В других действиях допустим сокращённый набор. Аргументы передаются по порядку либо по имени, например `$sla = "2 рабочих дня после получения"`.

Для переноса подписи используй соединение строк через `%newline()`. Для продолжения вызова на следующей строке исходника поставь `\` в конце предыдущей. `%breakline()` не является переносом текста подписи. Не экранируй произвольный пользовательский текст механически: проверь кавычки и разметку PlantUML, не меняя смысл.

## Условие

```plantuml
if ($ruleway_condition("Заявка согласована?", "РСЗ-03: решение")) then (да)
  ' Действия положительной ветви.
else (нет)
  ' Действия отрицательной ветви.
endif
```

`$ruleway_condition($question, $basis)` возвращает подпись. Оба поля обязательны. Основание должно существовать к моменту выбора, а работа по проверке и ответственный — находиться в предшествующем действии. Функция проверяет только непустоту строк. Подписи ответов и смысл переходов проверяет автор.

Для повтора:

```plantuml
repeat
  ' Действия подготовки, доработки и проверки.
repeat while ($ruleway_condition("В заключении есть замечания?", "РСЗ-02: последнее заключение")) is (да) not (нет)
```

Фрагменты с комментариями иллюстрируют конструкции; это не самостоятельные схемы. Все фактические действия оформляются `$ruleway_action`, обычные узлы `:Действие;` в редактируемом исходнике RulewayUML не используются.

## Начало и завершение

```plantuml
start
note right
$ruleway_start_label("Поступила заявка", "Заявка и приложенные документы")
end note

' Действия и переходы регламента.

stop
note right
$ruleway_end_label("Решение получено", "Инициатор получил решение")
end note
```

API: `$ruleway_start_label($event, $inputs = "")` и `$ruleway_end_label($outcome, $result = "")`. Первый аргумент обязателен; второй независим и скрывается при пустой строке. Маркеры `start`/`stop` и `note right` остаются явными. У каждой окончательной ветви свой исход. События и исходы — свободный текст автора, без ID и значений по умолчанию.

## Минимальный самостоятельный исходник

Файл предполагается рядом с каталогом `components/`. Это учебное содержание, не заготовка с вымышленными правилами для пользователя.

```plantuml
@startuml
!include components/action.puml
!include components/start.puml
!include components/end.puml
start
note right
$ruleway_start_label("Поступила заявка")
end note
$ruleway_action("РРЗ-01", "Зарегистрировать заявку", "Координатор", "Заявка зарегистрирована")
stop
note right
$ruleway_end_label("Заявка зарегистрирована")
end note
@enduml
```

Для условий дополнительно подключи `components/condition.puml`. Для параллельности используй стандартные `fork`, `fork again`, `end fork`; смысл ожидания определяется правилами регламента. Готовые схемы — в [справочнике маршрутов](routes.md).
