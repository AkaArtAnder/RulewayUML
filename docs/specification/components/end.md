# Завершение регламента

[Библиотека RulewayUML](../README.md) → Завершение

Компонент [`end.puml`](../../../components/end.puml) описывает, каким исходом закончился регламент или рассматриваемый фрагмент и какой результат получен. Описание располагается справа от стандартного маркера `stop`.

Исход выделен жирным. Необязательное поле **«Результат:»** выводится ниже через пустую строку: подпись жирная, значение обычное. Используются мятный фон, бирюзовая граница, DejaVu Sans 14, выравнивание слева и внутренние отступы. Все авторские исходы оформляются одинаково.

## Подключение и минимальный пример

Сохраните весь каталог `components/`, включая `assets/` и внутренние `.iuml`-файлы. Пример рассчитан на файл в соседнем каталоге `examples/`:

```plantuml
@startuml
!include ../components/action.puml
!include ../components/start.puml
!include ../components/end.puml

start
note right
$ruleway_start_label("Поступило обращение")
end note

$ruleway_action("РРО-01", "Зарегистрировать обращение", "Оператор", \
  "Обращение зарегистрировано")

stop
note right
$ruleway_end_label("Обращение зарегистрировано")
end note
@enduml
```

`end.puml` автоматически подключает общий стиль и внутреннюю сборку подписи. Начало и действия подключаются отдельно. Пути указываются относительно файла диаграммы.

## Параметры

`$ruleway_end_label($outcome, $result = "")`

Оба аргумента — строки; передавайте их в указанном порядке.

| Аргумент | Содержание | Обязательность |
| --- | --- | --- |
| `$outcome` | Конкретный исход, сформулированный автором регламента | Обязательно |
| `$result` | Итоговый документ, запись или состояние передачи результата | По необходимости |

Функция возвращает текст. После последнего действия укажите `stop`, затем разместите вызов в `note right … end note`. Сама функция не завершает процесс и не создаёт переходов.

Пустой результат (`""`) скрывается вместе с подписью и разделительным отступом. Если исход уже полностью описывает итог, повторять его в результате не нужно. Отдельный ID, ответственный и срок у завершения не задаются.

## Правила применения

- **Каждый исход явно задаёт автор.** Название — свободный текст; встроенных статусов, ограниченного списка или исхода по умолчанию нет. Автор определяет число и содержание завершений своего процесса.
- **Сначала выполните обязательную работу.** Передача результата и уведомление участника оформляются действиями перед `stop`. Подпись завершения описывает уже достигнутое состояние.
- **Различайте итоговые состояния.** Если пути заканчиваются по-разному, подпишите завершение каждого пути. Полноту исходов и правильность маршрутов проверяет автор.
- **Сохраняйте границы схемы.** «Проверка завершена» может означать оформленное заключение с замечаниями. Это завершение проверки, а не всего согласования. «Заявка передана на согласование» подходит для фрагмента подготовки.
- **Замечания могут требовать продолжения.** Когда регламент предусматривает доработку и повторную проверку, показывайте цикл; не заканчивайте весь процесс на обнаружении замечаний.
- **Не заменяйте завершением ожидание другой ветви.** Готовность одной параллельной работы и окончание всего процесса — разные состояния. Ожидание обязательных результатов задавайте конструкциями параллельной работы.

## Отдельные исходы ветвления

Фрагмент размещается после действия, принявшего решение по заявке, при подключённых `action.puml`, `condition.puml` и `end.puml`:

```plantuml
if ($ruleway_condition("Заявка согласована?", "РСЗ-01: решение по заявке")) then (да)
  $ruleway_action("РСЗ-02", "Сообщить о согласовании", "Согласующий", \
    "Инициатор получил подтверждение согласования")
  stop
  note right
  $ruleway_end_label("Заявка согласована", "Инициатор получил подтверждение согласования")
  end note
else (нет)
  $ruleway_action("РСЗ-03", "Сообщить об отказе", "Согласующий", \
    "Инициатор получил отказ с указанием причины")
  stop
  note right
  $ruleway_end_label("В согласовании отказано", "Инициатор получил отказ с указанием причины")
  end note
endif
```

Названия исходов здесь служат примерами заполнения. В своём регламенте автор задаёт необходимые формулировки. Полная схема — [два исхода решения](../../../examples/condition_decision.puml).

## Многострочный текст

Внутри подписи используйте `%newline()`:

```plantuml
$ruleway_end_label("Проверка заявки завершена," + %newline() + "заключение оформлено", "Перечень замечаний" + %newline() + "или отметка об их отсутствии")
```

Каждая строка исхода сохраняет жирное начертание, текст результата — обычное. Полная схема — [многострочные подписи границ](../../../examples/regulation_boundaries_long_text.puml).

## Возможности и ограничения

Пустой исход (`""`) вызывает ошибку `Ruleway: укажите исход завершения`. Пробелы вместо текста, полнота исходов, выполнение действий и фактическая передача результата не проверяются. Библиотека не исполняет процесс.

Компонент не назначает исходу цвет или категорию по его названию. Общие настройки примечаний находятся в `components/style.puml` и применяются также к другим `note` на схеме.

Примеры: [только обязательные поля](../../../examples/regulation_boundaries_minimal.puml), [завершение согласования](../../../examples/basic_regulation.puml), [завершение дочерней проверки](../../../examples/review_regulation.puml), [конец фрагмента подготовки](../../../examples/condition_rework.puml). Событие запуска описывается [компонентом начала](start.md).
