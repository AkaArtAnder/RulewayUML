# Условие регламента

[Библиотека RulewayUML](../README.md) → Условие

Компонент [`condition.puml`](../../../components/condition.puml) описывает выбор дальнейшего пути: задаёт вопрос и указывает основание для ответа. Используйте его после действия, которое проверило данные или зафиксировало решение, в ветвлении `if` или условии повтора `repeat while`.

В блоке вопрос выделен жирным и расположен по центру. Ниже, с отступом, слева отображается жирная подпись **«Основание:»** и обычный текст значения. Шрифт — DejaVu Sans, размер 14, как в действии; сверху и снизу оставлены внутренние отступы.

## Подключение и минимальный пример

Сохраните весь каталог `components/`, включая `assets/`. Пример рассчитан на файл в соседнем каталоге `examples/`:

```plantuml
@startuml
!include ../components/action.puml
!include ../components/condition.puml

start
$ruleway_action("РСЗ-01", "Принять решение по заявке", "Согласующий", \
  "Решение о согласовании или отказе")

if ($ruleway_condition("Заявка согласована?", "РСЗ-01: решение по заявке")) then (да)
  $ruleway_action("РСЗ-02", "Сообщить о согласовании", "Согласующий", \
    "Инициатор получил подтверждение согласования")
else (нет)
  $ruleway_action("РСЗ-03", "Сообщить об отказе", "Согласующий", \
    "Инициатор получил отказ с указанием причины")
endif
stop
@enduml
```

`condition.puml` автоматически подключает общий стиль. Для действий подключайте `action.puml` отдельно. Пути указываются относительно файла диаграммы.

## Параметры

`$ruleway_condition($question, $basis)`

Оба аргумента — обязательные строки, передаваемые в указанном порядке.

| Аргумент | Содержание | Пример |
| --- | --- | --- |
| `$question` | Конкретный вопрос, определяющий следующий переход | «В заключении есть замечания?» |
| `$basis` | Результат действия, документ или правило, по которому определяется ответ | «РСЗ-02: заключение» |

Функция возвращает оформленную подпись. Размещайте вызов внутри `if (...)` или `repeat while (...)`: сам вызов не создаёт узел или переходы. Подписи исходов задавайте стандартным синтаксисом PlantUML.

## Правила применения

- **Вопрос:** формулируйте так, чтобы ответ можно было однозначно получить из указанного основания. Вместо «Всё хорошо?» — «В заключении есть замечания?».
- **Основание:** называйте конкретный результат, документ или правило, доступное к моменту выбора пути. Для результата действия указывайте его ID и название результата. Код в основании ссылается на действие; отдельный ID условия не нужен.
- **Проверка и решение:** выполняются в предшествующем действии с ответственным и результатом. Условие показывает переход по этому результату; повторять ответственного и срок внутри условия не требуется.
- **Исходы:** подписывайте оба ответа бинарного вопроса — `да` и `нет`. Если ответ пока неизвестен или данных нет, явно опишите отдельный путь обработки такой ситуации; отсутствие ответа не означает «нет».
- **Доработка:** замечания ведут к исправлению и повторной проверке. Условие выхода из цикла должно опираться на результат последней проверки. При наличии лимита повторов укажите его и дальнейший исход при достижении лимита.
- **Краткость:** оставляйте в блоке вопрос и основание, а подробности проверки размещайте в инструкции действия или связанном документе.

## Возврат на доработку

Вместо ветвления условие можно использовать в стандартном цикле:

```plantuml
repeat
  $ruleway_action("РСЗ-01", "Подготовить или доработать заявку", "Инициатор", \
    "Заявка с документами и учтёнными замечаниями")
  $ruleway_action("РСЗ-02", "Проверить заявку", "Согласующий", \
    "Заключение: перечень замечаний или отметка об их отсутствии")
repeat while ($ruleway_condition("В заключении есть замечания?", "РСЗ-02: заключение")) is (да) not (нет)
```

Ответ «да» возвращает к подготовке заявки, «нет» выводит из цикла. Следующее действие задаётся после `repeat while`. Полная схема фрагмента подготовки к согласованию — [condition_rework.puml](../../../examples/condition_rework.puml); весь процесс — [основной пример](../../../examples/basic_regulation.puml) и [вариант без дорожек](../../../examples/basic_regulation_no_lanes.puml).

## Многострочный текст

Для переноса текста в вопросе или основании используйте `%newline()`. Например, условие цикла проверки комплекта документов:

```plantuml
repeat while ($ruleway_condition("Есть отсутствующие документы" + %newline() + "или документы с истёкшим сроком действия?", "РПД-02: чек-лист комплекта" + %newline() + "Перечень документов из правил регламента")) is (да) not (нет)
```

Каждая строка вопроса сохраняет жирное начертание и центрирование. Значение основания, включая продолжение на следующих строках, остаётся обычным и выровненным слева. Полный пример — [condition_long_text.puml](../../../examples/condition_long_text.puml).

## Возможности и ограничения

Пустой вопрос или основание (`""`) вызывают ошибку `Ruleway` с указанием незаполненного поля. Пробелы вместо содержимого, смысл вопроса, существование указанного действия и соответствие основания его результату автоматически не проверяются.

Компонент оформляет подпись: он не вычисляет ответ, не проверяет полноту ветвей и не управляет выполнением регламента. Правильность переходов и подписей исходов обеспечивает автор схемы. Отдельного API для многовариантного выбора нет.

Пример двух окончательных исходов — [condition_decision.puml](../../../examples/condition_decision.puml). В этом учебном сценарии допустим отказ; в основном примере замечания ведут к доработке.
