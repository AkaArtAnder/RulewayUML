# Действие регламента

[Библиотека RulewayUML](../README.md) → Действие

Компонент [`action.puml`](../../../components/action.puml) описывает один шаг регламента: что нужно сделать, кто отвечает и какой результат должен получиться. В блоке отображаются идентификатор и название, ответственный и результат. По необходимости добавляются инструкция или чек-лист, срок и ссылка на дочерний регламент.

## Подключение и минимальный пример

Сохраните весь каталог `components/`, включая `assets/`. Пример рассчитан на файл в соседнем каталоге `examples/`:

```plantuml
@startuml
!include ../components/action.puml
start
$ruleway_action("РСЗ-01", "Согласовать заявку", "Согласующий", "Решение принято")
stop
@enduml
```

`action.puml` автоматически подключает общий стиль. Начало, завершение, условия, циклы и дорожки описывайте вокруг вызовов стандартным синтаксисом PlantUML. Каждое действие оформляйте через `$ruleway_action(...)`.

## Параметры

`$ruleway_action($id, $name, $responsible, $result, $instruction = "", $sla = "", $subregulation = "")`

Все аргументы — строки. Их можно передавать по порядку или по имени.

| Аргумент | Содержание | Обязательность |
| --- | --- | --- |
| `$id` | Идентификатор действия, например `РСТ-03` | Обязателен |
| `$name` | Название действия, например «Проверить заявку» | Обязательно |
| `$responsible` | Роль с подписью «Ответственный» | Обязательна |
| `$result` | Ожидаемый итог: описание, именованная ссылка на шаблон или их сочетание | Обязателен |
| `$instruction` | Текст или перечень пунктов под заголовком «Инструкция / чек-лист» | Необязательна |
| `$sla` | Норматив времени с подписью «Срок» | Необязателен |
| `$subregulation` | Именованная ссылка на дочерний регламент | Необязательна |

Первые четыре значения не могут быть пустыми. Последние три независимы: можно заполнить любые из них или пропустить все. Значение `""` скрывает соответствующее поле вместе с подписью и отступом. Чтобы пропустить инструкцию и указать срок, передайте именованный `$sla` либо пустую строку на месте инструкции.

## Правила заполнения

- **Идентификатор:** кириллическая `Р` + два символа аббревиатуры регламента + дефис + две цифры. Выберите аббревиатуру в начале работы: `РСТ-03` — третье действие регламента «Сущности трекера». Задавайте номера вручную в общем порядке действий, сохраняйте ведущий ноль и уникальность внутри регламента. Компонент проверяет формат ID; выбор аббревиатуры, уникальность и порядок проверяет автор.
- **Название:** одно действие, названное глаголом — «Подготовить заявку», «Оформить заключение».
- **Ответственный:** роль, выполняющая действие. Заполняйте её независимо от наличия дорожек на схеме.
- **Результат:** что должно быть получено после действия; при необходимости добавьте ссылку на шаблон.
- **Инструкция / чек-лист:** краткое пояснение или пункты проверки. Нумерацию пунктов задавайте в тексте. Длинные подробности выносите в связанный документ или подрегламент.
- **Срок:** указывайте длительность и точку отсчёта либо событие, к которому действие должно завершиться.

## Пример со всеми параметрами

Вместо вызова из минимального примера можно вставить:

```plantuml
$ruleway_action( \
  $id = "РСЗ-02", \
  $name = "Проверить заявку", \
  $responsible = "Согласующий", \
  $result = "Заключение с перечнем замечаний" + %newline() + "[[materials/review_template.html Шаблон заключения]]", \
  $instruction = "1. Проверить цель заявки." + %newline() + "2. Сверить комплект документов." + %newline() + "3. Зафиксировать замечания.", \
  $sla = "1 рабочий день после получения", \
  $subregulation = "[[review_regulation.svg Подрегламент: проверка заявки]]" \
)
```

Для переноса вызова в исходнике ставьте `\` в конце продолжаемой строки. Для переноса текста внутри блока соединяйте части через `%newline()`; буквальный `\n` и `%breakline()` для этого не используйте. Текст с двойными кавычками можно заключить в одинарные: `'Проверить "цель" заявки'`.

## Ссылки и применение в процессе

В параметрах можно использовать Creole-разметку PlantUML и именованные ссылки вида `[[адрес Название ссылки]]`. Ссылка на подрегламент открывает отдельную схему; её содержимое не встраивается в действие. Компонент не проверяет доступность адресов. Размещение связанных файлов описано в [правилах экспорта](../README.md#экспорт-и-ссылки).

Полные схемы: [согласование заявки](../../../examples/basic_regulation.puml), [тот же процесс без дорожек](../../../examples/basic_regulation_no_lanes.puml) и [дочерняя проверка заявки](../../../examples/review_regulation.puml).
