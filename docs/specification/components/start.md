# Начало регламента

[Библиотека RulewayUML](../README.md) → Начало

Компонент [`start.puml`](../../../components/start.puml) описывает, какое событие запускает регламент и какие сведения или материалы нужны на входе. Описание располагается справа от стандартного маркера `start`.

Событие выделено жирным. Необязательное поле **«Входы:»** выводится ниже через пустую строку: подпись жирная, значение обычное. Мятный фон, бирюзовая граница, DejaVu Sans 14, выравнивание слева и внутренние отступы соответствуют оформлению библиотеки.

## Подключение и минимальный пример

Сохраните весь каталог `components/`, включая `assets/` и внутренние `.iuml`-файлы. Пример рассчитан на файл в соседнем каталоге `examples/`:

```plantuml
@startuml
!include ../components/action.puml
!include ../components/start.puml
!include ../components/end.puml

start
note right
$ruleway_start_label("Поступило обращение")
end note

$ruleway_action("РРО-01", "Зарегистрировать обращение", "Оператор", \
  "Обращение зарегистрировано")

stop
note right
$ruleway_end_label("Обращение зарегистрировано")
end note
@enduml
```

`start.puml` автоматически подключает общий стиль и внутреннюю сборку подписи. Для действий и завершения подключайте соответствующие компоненты отдельно. Пути указываются относительно файла диаграммы.

## Параметры

`$ruleway_start_label($event, $inputs = "")`

Оба аргумента — строки; передавайте их в указанном порядке.

| Аргумент | Содержание | Обязательность |
| --- | --- | --- |
| `$event` | Событие запуска, сформулированное автором регламента | Обязательно |
| `$inputs` | Сведения, документы или материалы для первого действия | По необходимости |

Функция возвращает текст, а не создаёт маркер начала. Сначала укажите `start`, затем разместите вызов в `note right … end note`, как в примере. Не оформляйте начало обычным action-блоком.

Пустые входы (`""`) скрываются вместе с подписью и разделительным отступом. Отдельный ID, ответственный и срок у начала не задаются.

## Правила применения

- **Событие формулирует автор.** Это свободный текст о наступившем факте, после которого начинается первое действие. Готового справочника событий нет.
- **Согласуйте событие с границами процесса.** Если первое действие готовит заявку, событие «Готовая заявка получена» описывает начало другого, более узкого процесса. Для подготовки можно указать возникновение потребности в согласовании.
- **Перечисляйте уже доступные входы.** Документ, который создаётся первым действием, не должен требоваться готовым на входе. Входы можно опустить, если событие уже однозначно их называет.
- **Работу описывайте действием.** Регистрация, проверка применимости и принятие решения выполняются участником; подпись начала их не выполняет.
- **Дорожку выбирайте перед началом.** Если схема использует дорожки, укажите `|Роль|` перед `start`; ответственным за работу остаётся исполнитель первого действия.
- **Доработку возвращайте к действию.** Повтор внутри процесса не требует нового события запуска.

## Входы и многострочный текст

Замените вызов подписи в примере на нужное содержание, например:

```plantuml
$ruleway_start_label("Заявка передана на проверку", "Заявка и приложенные документы")
```

Для ручного переноса используйте `%newline()`:

```plantuml
$ruleway_start_label("Заявка с приложенными документами" + %newline() + "передана на проверку", "Сведения о цели обращения" + %newline() + "и документы, приложенные инициатором")
```

Каждая строка события выделяется жирным; текст входов остаётся обычным. Полная схема — [многострочные подписи границ](../../../examples/regulation_boundaries_long_text.puml).

## Возможности и ограничения

Пустое событие (`""`) вызывает ошибку `Ruleway: укажите событие начала`. Пробелы вместо текста, наличие документов и соответствие события первому действию автоматически не проверяются. Автор определяет содержание и применимость регламента.

Функция только оформляет подпись. Она не запускает процесс, не создаёт действий или дорожек и не выбирает точку начала. Общие настройки примечаний находятся в `components/style.puml` и применяются также к другим `note` на схеме.

Примеры: [только обязательные поля](../../../examples/regulation_boundaries_minimal.puml), [согласование с дорожками](../../../examples/basic_regulation.puml), [без дорожек](../../../examples/basic_regulation_no_lanes.puml), [начало дочерней проверки](../../../examples/review_regulation.puml). Итог процесса описывается [компонентом завершения](end.md).
