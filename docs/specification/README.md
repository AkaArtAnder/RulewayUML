# Библиотека RulewayUML

Для работы с ИИ-агентом доступна [первая сборка скилла](agent_skill.md): создание и редактирование регламентов, исходники, SVG и HTML. Совместимость с конкретными агентными системами и Яндекс Wiki проверяется отдельно.

RulewayUML — библиотека компонентов PlantUML для описания регламентов диаграммами деятельности. Схема показывает действия, ответственных, ожидаемые результаты и порядок переходов; ссылки связывают шаги с инструкциями, шаблонами и дочерними регламентами.

Библиотека оформляет описание процесса. Сроки и чек-листы служат правилами для исполнителя; автоматического контроля сроков и учёта выполнения нет.

## Доступные возможности

| Элемент | Применение |
| --- | --- |
| [Действие](components/action.md) | Шаг с идентификатором, названием, ответственным и результатом; при необходимости — инструкция, срок и ссылка на подрегламент |
| [Условие](components/condition.md) | Вопрос и основание для выбора пути в ветвлении или цикле |
| [Начало](components/start.md) | Событие запуска и необязательные входы рядом со стандартным маркером начала |
| [Завершение](components/end.md) | Авторский исход и необязательный результат рядом со стандартным маркером завершения |
| [Общий стиль](../../components/style.puml) | Единые цвета, шрифт, оформление блоков и фирменный знак; подключается автоматически каждым компонентом |

Ветвления, циклы, параллельные ветви и дорожки задаются стандартными конструкциями PlantUML. Компонент условия формирует подпись внутри `if` и `repeat while`. Начало и завершение формируют подписи в `note right` после стандартных `start` и `stop`.

## Подключение

Базовая версия проекта — PlantUML `1.2025.10`, совпадающая с версией движка проверенной пользователем Яндекс Wiki. В контейнере задан лимит `PLANTUML_LIMIT_SIZE=4096`. Сохраняйте исходники в UTF-8. Скопируйте весь каталог [`components/`](../../components/), включая `assets/` и внутренние `.iuml`-файлы, в свой проект. В начале диаграммы после `@startuml` подключите нужные компоненты; путь указывается относительно файла диаграммы:

```plantuml
!include ../components/action.puml
!include ../components/condition.puml
!include ../components/start.puml
!include ../components/end.puml
```

Минимальные схемы и параметры приведены в описаниях [действия](components/action.md#подключение-и-минимальный-пример), [условия](components/condition.md#подключение-и-минимальный-пример), [начала](components/start.md#подключение-и-минимальный-пример) и [завершения](components/end.md#подключение-и-минимальный-пример). Данные конкретного регламента размещайте в своём `.puml`, а общие настройки оформления меняйте в `components/style.puml`. Название схемы задавайте через `title`: верхний колонтитул `header` используется для знака библиотеки.

## Правила построения регламента

- Каждое действие оформляйте через `$ruleway_action(...)`, заполняя идентификатор, название, ответственного и результат.
- Сохраняйте ID существующих действий при редактировании и перемещении. Новому действию назначайте свободный номер; порядок выполнения задаётся переходами, а не числовой частью ID.
- Начало, завершение и переходы задавайте явно. Для условий используйте `if`, для повторов — `repeat`, для параллельных действий — `fork`.
- Описывайте событие запуска через `$ruleway_start_label(...)`, каждый исход — через `$ruleway_end_label(...)` в примечании у соответствующего маркера. Названия формулирует автор регламента; перечня встроенных событий или исходов нет.
- В `if` и `repeat while` задавайте вопрос и основание через `$ruleway_condition(...)`, подписывайте исходы. Проверку данных или принятие решения оформляйте предшествующим действием.
- Дорожки `|Роль|` добавляйте, когда они помогают читать процесс. Поле «Ответственный» заполняется и при наличии дорожек, и без них.
- При замечаниях показывайте возврат на доработку и повторную проверку. Если число повторов ограничено, укажите ограничение у цикла и дальнейший исход при его достижении.
- Сохраняйте подписи краткими, а подробные инструкции и дочерние процессы связывайте со схемой ссылками.

## Предпросмотр в VS Code

Для работы с примерами репозитория откройте проект через **Dev Containers: Reopen in Container**, затем вызовите **PlantUML: Preview Current Diagram** (`Alt+D`). [Настройки проекта](../../.vscode/settings.json) выбирают локальный JAR `/opt/plantuml/plantuml.jar` из [Dev Container](../../.devcontainer/devcontainer.json) с версией `1.2025.10`.

Если контейнер уже был создан с другой версией, выполните **Dev Containers: Rebuild Container**. После пересборки `plantuml -version` должен показывать `1.2025.10`; затем заново откройте предпросмотр. Изменение Dockerfile само по себе не обновляет работающий контейнер.

## Экспорт и ссылки

В терминале Dev Container из корня репозитория:

```bash
plantuml -charset UTF-8 -failfast2 -tsvg -o /tmp/ruleway-examples examples/*.puml
plantuml -charset UTF-8 -failfast2 -tpng -o /tmp/ruleway-examples examples/*.puml
cp -R examples/materials /tmp/ruleway-examples/
```

SVG сохраняет ссылки, PNG — только их подписи. Относительные ссылки разрешаются от готового SVG, поэтому размещайте связанные схемы и каталог `materials/` рядом с ним. При переносе примеров в свой регламент заменяйте адреса и подписи, включая обратные ссылки.

Для навигации открывайте SVG напрямую в браузере по HTTP. Доступность ссылок при встраивании в wiki, Markdown или HTML как изображения зависит от среды просмотра; проверяйте переходы в месте публикации.

Для блока PlantUML Яндекс Wiki используйте `*_portable.puml` из [общего экспорта скилла](agent_skill.md#результат). В код включаются стили и векторный знак; локальные `!include` не нужны. Этот же комплект содержит SVG и HTML для браузера; повторная сборка для другой среды не требуется. Условие и знак основного примера проверены в Wiki на версии `1.2025.10`; кликабельность проверяется отдельно.
