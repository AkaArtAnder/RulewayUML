# Скилл для ИИ-агентов

[Библиотека RulewayUML](README.md) → Скилл

Скилл `rulewayuml` помогает построить схему по артефактам регламента из других инструментов, написать регламент с нуля или отредактировать существующий исходник RulewayUML. Он сохраняет постоянные ID и восстанавливает очередность по переходам и зависимостям. Пользователь задаёт ссылки и предметные правила.

В первом режиме можно передать незавершённые описания, таблицы, заметки и схемы. Агент переносит найденные сведения в диаграмму и показывает несостыковки связей, противоречия и неполные обязательные поля с указанием источников. Он не рекомендует, чем наполнить диаграмму, и не добавляет недостающие правила. При пробелах вы получаете черновик с явными пометками; несвязанные участки могут быть представлены отдельными фрагментами. Затем можно поручить дополнение или редактирование схемы.

Текущая сборка имеет версию `0.0.1`. Версия задаётся тремя числами без служебного суффикса. Формат — каталог с `SKILL.md`, справочниками, примерами, компонентами и локальным экспортёром. Для Wiki и браузера используется одно окружение PlantUML `1.2025.10` и один комплект результатов. Предметные инструкции не зависят от конкретного агента. Отображение условия и векторного знака основной схемы в Яндекс Wiki подтверждено пользователем. Пять подготовленных учебных случаев трёх режимов и полный локальный технический тест пройдены 2026-10-03; реальные пользовательские случаи разработки с нуля и редактирования, кликабельность в Wiki и совместимость с другими агентными системами проверяются отдельно.

## Подключение

Скачайте из репозитория [архив `rulewayuml-0.0.1.zip`](../../dist/rulewayuml-0.0.1.zip) и распакуйте его. В нём один каталог `rulewayuml`; переносите его целиком, включая `assets/`, `references/` и `scripts/`.

- Если система поддерживает скиллы с `SKILL.md`, поместите каталог в её каталог локальных скиллов по правилам этой системы.
- Если такой механизм отсутствует, укажите агенту прочитать `rulewayuml/SKILL.md` и следовать ему, предоставив доступ к соседним ресурсам.
- Для полного результата агенту нужны чтение и запись локальных файлов, диалог с пользователем и запуск Docker либо доступ к Dev Container. Один доступ к тексту инструкций не обеспечивает экспорт SVG.

Скилл не устанавливается в конкретную систему автоматически и не меняет её настройки. На этапе разработки пакет собирается из репозитория; порядок сборки хранится в [контексте задачи](../tasks/2026_09_22_agent_skill.md). Для разработки используется служебный каталог `.tools/skill_builder/`. Сборщик создаёт готовый ZIP в `dist/`, добавляя к шаблону инструкций компоненты, примеры и окружение. Для установки нужен ZIP; служебный каталог не является подключённым навыком проекта.

Для работы с готовой схемой откройте проект, где доступен её `.puml`, и передайте агенту путь к файлу вместе с точным описанием правки. Например: «Используй скилл RulewayUML. В схеме `process.puml` добавь регистрацию результата перед согласованием; сохрани существующие ID, ссылки и остальные поля». Агент должен выдать отдельную обновлённую копию и соответствующий ей экспортный комплект, не переписывая исходную схему без явного указания.

## Как обратиться к агенту

- «Используй скилл RulewayUML. Построй схему по этим заметкам и таблице регламента, сохрани мои термины и правила. Материалы ещё не завершены. Выдай исходник, SVG, HTML и анализ разрывов связей и неполных элементов без рекомендаций по наполнению».
- «Подготовь исходник для блока PlantUML Яндекс Wiki и сохрани редактируемую версию схемы».
- «Помоги написать регламент обработки заявок с нуля. Уточни недостающие правила и подготовь текст со схемой».
- «В этой схеме добавь регистрацию заключения перед согласованием. Сохрани существующие ID и ссылки, новому шагу назначь свободный номер».

При разборе артефактов агент фиксирует пробелы в анализе, не требуя сначала завершить регламент. При разработке и редактировании он уточняет пропуски, влияющие на смысл. Отсутствие необязательных полей само по себе не считается ошибкой; сроки из учебных примеров не переносятся в ваш процесс автоматически.

## Результат

Экспорт создаёт новый каталог с редактируемыми исходниками и зависимостями в `source/`, SVG, HTML и отдельным кодом для вставки в `diagrams/`. При работе по артефактам агент сопровождает схему анализом связей и полноты элементов; готовность этого разбора не означает завершённость самого регламента. При разработке с нуля агент также выдаёт текст регламента. При редактировании — краткий перечень изменений.

HTML использует SVG как отдельный документ, чтобы сохранить внутренние ссылки. Единый код для вставки `*_portable.puml` развёрнут и не требует локальных `!include`; этот же файл вставляется в блок PlantUML Wiki. Сохраняйте оригинальные исходники с компонентами для последующего редактирования.

Версия и лимит читаются из `assets/runtime/Dockerfile`, скопированного из окружения проекта. Используется один Docker-образ `rulewayuml-dev:plantuml-1.2025.10`, собираемый без дополнительных аргументов. Java 17, Python 3, Graphviz и DejaVu Sans находятся внутри контейнера; отдельная установка на компьютер не требуется. Экспорт выполняется без сети.

```bash
bash scripts/export.sh /путь/к/work /путь/к/новому_результату regulation.puml
```

Подробные команды, требования к окружению и ограничения включены в пакет в `references/export.md`. Публикация в Wiki или на хостинге не входит в автоматический экспорт.

При обновлении с `0.1.1-dev` замените каталог скилла целиком: параметр `--target` удалён, отдельный файл `*_yandex_wiki.puml` больше не создаётся. Если у вас есть автоматические команды экспорта, уберите выбор профиля и используйте `*_portable.puml`. Пользовательские рабочие исходники и ранее выданные файлы сохраняются.
