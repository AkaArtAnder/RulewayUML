## Предлагаемый вид

Один вариант оформления для обоих элементов: стандартный маркер `start` или `stop` и блок описания справа от него. Описание задаётся обычным `note right`; функции макета формируют только текст. Стандартный синтаксис примечаний описан в [документации PlantUML](https://plantuml.com/activity-diagram-beta#notes).

| Свойство | Начало | Завершение |
| --- | --- | --- |
| Главная строка | Событие, заданное автором | Исход, заданный автором |
| Начертание главной строки | Жирное | Жирное |
| Дополнительная строка | **Входы:** обычный текст значения | **Результат:** обычный текст значения |
| При пустом дополнительном поле | Подпись и промежуток перед ней скрыты | Подпись и промежуток перед ней скрыты |

Параметры оформления заданы в [boundary_design.iuml](boundary_design.iuml):

- DejaVu Sans, размер 14, текст `#142D3B` — как в действии и условии.
- Мятный фон `#E5F5F1`, бирюзовая граница `#087F74` толщиной 1.5.
- Выравнивание текста слева, внутренний отступ 12, `MaximumWidth 330`.
- Между главным текстом и дополнительным полем — пустая строка. Заголовки из нескольких строк форматируются построчно.
- Одинаковое оформление всех исходов. Названия и смысл задаёт автор; предустановленных статусов и цветов успеха/отказа нет.

Настройки локальны для макетов и относятся к их примечаниям. Общий стиль библиотеки не менялся. Блок описания не является действием, поэтому не получает ID, ответственного или место в нумерации шагов.

## Что открыть

Начните с [full_fields.puml](full_fields.puml): начало и завершение с обоими полями рядом с существующим компонентом действия.

| Макет | Содержание |
| --- | --- |
| [Полное заполнение](full_fields.puml) | Дочерняя проверка заявки: событие и входы, исход и результат |
| [Минимальное заполнение](minimal.puml) | Только событие начала и исход завершения, без пустых секций |
| [Два исхода](two_outcomes.puml) | Отдельное завершение после уведомления на каждой ветви условия |
| [Дорожки и переносы](swimlanes.puml) | Основной цикл согласования, две роли, многострочные событие, входы и результат |

Это самостоятельные учебные диаграммы для оценки вида. Формулировки не задают справочник библиотеки. Все действия используют `$ruleway_action`, условия — `$ruleway_condition`; макеты не добавляют обычных activity-узлов для обозначения границ.

## Использование определений макета

В исходниках макетов подключён `boundary_design.iuml`. Фрагмент начала:

```plantuml
start
note right
$ruleway_design_start_label("Заявка передана на проверку", "Заявка и приложенные документы")
end note
```

Фрагмент завершения, размещаемый после последнего обязательного действия:

```plantuml
stop
note right
$ruleway_design_end_label("Проверка завершена", "Заключение оформлено")
end note
```

Вторые аргументы необязательны. Для ручного переноса текста используется `%newline()`. Событие и исход проверяются только на непустую строку. Эти функции служат макету; их имена и способ применения не являются публичным API.
