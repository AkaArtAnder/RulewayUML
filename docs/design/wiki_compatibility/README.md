# Прототип векторного знака для Яндекс Wiki

Статус на 2026-09-22: принят пользователем после успешной вставки настоящего знака в Wiki; перенесён в публичные компоненты. Этот каталог сохраняет преобразователь и образец для воспроизведения. Проверены PlantUML `1.2025.10` и `1.2026.5`. Скилл `0.1.1-dev` использует отдельный профиль Wiki. История — [контекст совместимости](../../tasks/2026_09_22_wiki_compatibility.md).

В диагностике пользователя PNG и обычный спрайт исчезли из заголовка и примечания, а SVG-спрайт из залитого контура отображается в обоих местах. Обычный спрайт также превращается в PNG внутри результата SVG. Поэтому прототип формирует знак только из `path`, без `image`, внешних ресурсов, градиентных ссылок и преобразований групп.

## Подготовка знака

[generate_vector_logo.java](generate_vector_logo.java) читает неизменённый [ruleway-icon.svg](../../ruleway_design/ruleway-icon.svg). Контуры обводок преобразуются в залитые фигуры средствами Java2D. Переносы групп применяются к координатам; размер результата — 48 × 48. Плавный переход от тёмно-синего к бирюзовому приближён 64 переходами цвета с перекрытием фигур, чтобы избежать прозрачных швов. Получается 134 векторных контура, около 39 КБ до включения в схему.

Это преобразователь конкретного знака, не универсальный конвертер SVG: геометрия градиента закреплена по оригиналу; проверка SHA-256 останавливает выполнение, если исходник изменился. Дизайн-ресурс не перезаписывается. Дополнительные зависимости не нужны; используется существующий JDK 17 в Docker.

[build_preview.py](build_preview.py) создаёт новый каталог результатов, запускает преобразование и разворачивает текущий основной пример без дорожек. После переноса в библиотеку знак и совместимое условие уже поступают из публичных компонентов; дополнительные замены в коде не нужны. Заголовок использует `<size:13><$ruleway_logo></size>`: размер шрифта компенсирует масштабирование спрайтов относительно стандартного размера 13, сохраняя знак 48 × 48 при общем стиле заголовка 10. Ресурс защищён от повторного определения; при обновлении библиотеки сгенерированный `ruleway_vector_logo.iuml` копируется в `components/assets/ruleway_logo.iuml`.

Результат содержит `wiki_vector_logo.puml` для вставки без локальных включений, короткую проверку `icon_probe.puml`, векторный ресурс `.iuml`, SVG/PNG обеих версий и `report.json`. Это комплект проверки оформления, не полный экспорт регламента: цели учебных ссылок не копируются и переходы в Wiki не проверяются.

## Воспроизведение

Команда из корня проекта; каталог `/tmp/ruleway_wiki_icon_output` должен быть новым. JAR `1.2025.10` предварительно получают из [официального выпуска](https://github.com/plantuml/plantuml/releases/tag/v1.2025.10) внутри Docker. В текущей проверке он сохранён в `/tmp/ruleway_wiki_compat_20250922/plantuml-1.2025.10.jar`.

```bash
mkdir -p /tmp/ruleway_wiki_icon_output
docker run --rm --network none --user "$(id -u):$(id -g)" \
  --mount "type=bind,src=$PWD,dst=/workspace,readonly" \
  --mount "type=bind,src=/tmp/ruleway_wiki_compat_20250922,dst=/old,readonly" \
  --mount "type=bind,src=/tmp/ruleway_wiki_icon_output,dst=/results" \
  --entrypoint python3 rulewayuml-dev:plantuml-1.2026.5 \
  /workspace/docs/design/wiki_compatibility/build_preview.py \
  /results/preview /old/plantuml-1.2025.10.jar
```

Проверяются версии движков, успешный SVG/PNG-экспорт, наличие контуров и отсутствие растровых вставок/служебных тегов. PNG обеих версий и SVG версии Wiki просмотрены; браузерное сравнение оригинала и копии на размерах 48 и 256 пикселей не выявило искажения формы. Последующая вставка настоящего знака в Wiki подтверждена пользователем отдельно от локальных проверок.

Механизм: [SVG-спрайты PlantUML](https://plantuml.com/sprite). Для обычной выдачи результата используйте экспортёр скилла и его профиль `yandex-wiki`; этот каталог нужен для воспроизведения преобразования знака. Сгенерированные копии пакета вручную не редактируются.
