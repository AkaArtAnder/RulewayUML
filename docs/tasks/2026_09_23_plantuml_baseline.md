# Единая базовая версия PlantUML

Дата начала: 2026-09-23.
Статус: завершена, принято владельцем 2026-09-23. Визуальная проверка проведена успешно; базовые версии окружения согласованы.

## Задача и границы

Владелец поручил сделать версию PlantUML, используемую в его Яндекс Wiki, основой проекта. Несколько версий окружения и вариантов сборки увеличивают время работы агента. Подтверждённая пользователем версия сервиса — `1.2025.10`, лимит размера — 4096.

Владелец берёт проверку тестовых примеров на себя. При этом переходе агент не запускает синтаксические проверки схем, рендеринг, визуальное ревью, `tests/environment/check.sh`, `tests/components/check_action.sh` или `tests/skill/check.py` и не пересоздаёт готовые SVG/PNG.

На этапе перехода действовало уточнение: скилл не менять. Запрос о быстром предпросмотре и отложенной итоговой генерации временно неактуален. Исходники скилла, профили, экспортёр, спецификация скилла и собранные пакеты остаются прежними. Удаление профилей — следующий отдельный шаг после успешного перехода и возвращения владельца к этой задаче.

## Вариант перехода и изменения

- В `.devcontainer/Dockerfile` базовое значение `ARG PLANTUML_VERSION` изменено с `1.2026.5` на `1.2025.10`; `PLANTUML_LIMIT_SIZE=4096` задан явно. Для обычной сборки дополнительные аргументы не нужны.
- Java 17, Debian Bookworm, DejaVu Sans и прочие зависимости сохраняются. Graphviz остаётся пакетным из Debian; версия сервера Wiki `14.0.1` этим не воспроизводится. Совпадение версии PlantUML не означает полную копию инфраструктуры Wiki.
- `.devcontainer/devcontainer.json` уже строит этот Dockerfile без переопределения версии; `.vscode/settings.json` использует `/opt/plantuml/plantuml.jar`. CLI и предпросмотр после пересборки используют один JAR.
- Компоненты, API, данные регламентов и исходники схем не требуют новых изменений по имеющимся результатам. Условие без `<center>`/`<left>` и векторный знак уже были приняты пользователем в Wiki. Предыдущие проверки `1.2025.10` записаны в [контексте совместимости](2026_09_22_wiki_compatibility.md); они не выдаются за новую приёмку перехода.
- Актуальные инструкции по версии и пересборке обновлены в руководстве библиотеки и контексте. Исторические версии в отчётах о прошлых проверках сохранены.

## Проверка окружения без схем

Основной образ пересобран из Dockerfile без `--build-arg`; сборка завершилась с кодом 0, слои зависимостей взяты из кэша. Образ: `rulewayuml-dev:plantuml-1.2025.10`, ID `sha256:887ab266a3edf2c9b49d4f2b6c1b5fb5600b663c21ede156e4bd2b5289a3ee59`. Действующий пользовательский Dev Container автоматически не заменяется.

В новом временном контейнере без сети, от пользователя `vscode`, подтверждены PlantUML `1.2025.10`, Java `17.0.20.1`, Graphviz `2.43.0`, кодировка UTF-8 и лимит 4096. Проверялись только сведения об окружении; примеры, схемы и готовые изображения не проверялись и не создавались. Хеши исходников скилла, экспортёра, тестов, компонентов и примеров совпадают с состоянием до работы. Скилл и архивы не пересобирались.

Проверены 118 локальных ссылок обновлённой документации и согласованность Dockerfile, Dev Container и пути JAR в VS Code. `git diff --check` проходит.

```sh
docker build --tag rulewayuml-dev:plantuml-1.2025.10 \
  --file .devcontainer/Dockerfile .devcontainer

docker run --rm --network none --user vscode \
  --entrypoint sh rulewayuml-dev:plantuml-1.2025.10 \
  -c 'set -eu
plantuml -version
java -version
dot -V
printenv PLANTUML_LIMIT_SIZE'
```

## Передача на проверку и приёмка

В VS Code выполнить **Dev Containers: Rebuild Container**, убедиться, что `plantuml -version` выводит `1.2025.10`, и открыть нужные примеры через `Alt+D`. Старый контейнер сохраняет прежний JAR до пересборки.

На момент передачи окружения скилл `0.1.1-dev` оставался в прежнем состоянии: `local` требует `1.2026.5`, `yandex-wiki` — `1.2025.10`. Поэтому его обычный экспорт внутри нового Dev Container отклонит несовпадение версии. Это известное временное различие этапов, а не требование второй версии для самой библиотеки; на том этапе переход скилла не выполнялся.

2026-09-23 владелец сообщил: «Визуальная проверка проведена успешно. Можно фиксировать эти версии окружения». Приняты PlantUML `1.2025.10`, Java 17 (проверена `17.0.20.1`), Graphviz `2.43.0`, Debian Bookworm и лимит 4096. Основание приёмки отображения — проверка владельца; повторный рендеринг агентом не выполнялся. Последующим поручением разрешено привести скилл к единому окружению без профилей; эта работа продолжается в [задаче скилла](2026_09_22_agent_skill.md).
