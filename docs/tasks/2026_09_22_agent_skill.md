# Скилл для подготовки регламентов RulewayUML

Дата начала: 2026-09-22.
Статус: в работе — версия `0.1.2-dev` переводит скилл на единое принятое окружение PlantUML `1.2025.10` без профилей. Три поведенческих сценария ещё не пройдены. История совместимости — в [отдельном контексте](2026_09_22_wiki_compatibility.md).

Общий контекст: [docs/context.md](../context.md). Инструкции и реестр: [AGENTS.md](../../AGENTS.md).

Актуальная структура с 2026-09-23: разработка централизована в [`.tools/skill_builder/`](../../.tools/skill_builder/AGENTS.md), выдаётся только ZIP в `dist/`. Старые пути ниже сохранены в истории этапов; текущая команда сборки описана в служебном `AGENTS.md`.

## Запрос и исходное состояние

Владелец описал два сценария локального скилла: преобразовать готовый регламент в личном формате пользователя в схему или помочь написать регламент с нуля. Ожидаемый результат — исходный код схемы для вставки и качественный SVG для документа. Сначала запрошены рекомендации без изменений; после обсуждения владелец предложил начать движение по пунктам.

Работа началась с границ первой версии и проекта спецификации поведения с двумя эталонными сценариями. При продолжении владелец добавил третий сценарий — редактирование уже существующей схемы RulewayUML. На начальном этапе установка и готовый экспорт ещё не были реализованы; текущее состояние приведено ниже.

В библиотеке приняты действие, условие, начало, завершение и общий стиль. Пользовательский API описан в [спецификации библиотеки](../specification/README.md). Есть Docker / Dev Container с PlantUML `1.2026.5`, примеры и проверки окружения/действия. Отдельного скилла, пакета распространения и команды экспорта для его пользователя нет.

До начала работы в рабочем дереве уже изменены `AGENTS.md`, `docs/context.md`, `docs/action_component_spec.md` и `docs/tasks/2026_09_22_action_component.md`. Эти правки сохраняются. Первоначально последние два файла не относились к задаче; позднее новое решение владельца о постоянных ID потребовало обновить ТЗ и дополнить историю действия, сохранив прежние изменения и завершённый статус.

## Границы текущего этапа

- Подготовить отдельную проектную спецификацию; отличать требования пользователя, существующие правила библиотеки и предлагаемые решения.
- Описать преобразование готового регламента, разработку с нуля и редактирование существующей схемы RulewayUML, существенные уточнения, смысловую проверку и состав результата.
- Подготовить три учебных сценария для последующей проверки поведения; не выдавать их за реальные регламенты или выполненные испытания.
- Зафиксировать уточнения владельца: переносимость между популярными агентными системами, структура Codex как основа оформления; Яндекс Wiki и HTML в браузере как целевые среды результата.
- Сохранять API, оформление и существующие пользовательские примеры. Отображение новых образцов подтверждено владельцем. Для нового экспортёра разрешённая работа включает его техническую проверку и необходимый полный Python 3 в Docker; прежние тесты завершённых компонентов не запускаются повторно.
- Собирать переносимый пакет в репозитории; не устанавливать его в агентную систему и не публиковать без соответствующей задачи.
