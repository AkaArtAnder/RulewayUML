# Совместимость RulewayUML с Яндекс Wiki

Дата начала: 2026-09-22.
Статус: завершена в части оформления и подготовки кода — условие и настоящий векторный знак приняты пользователем в Wiki, изменения перенесены в компоненты, скилл `0.1.1-dev` и демокомплекты пересобраны.

Общий контекст: [docs/context.md](../context.md). Связанная задача: [скилл](2026_09_22_agent_skill.md). Прототип: [docs/design/wiki_compatibility/](../design/wiki_compatibility/README.md).

## Запрос и результаты диагностики

При вставке развёрнутой демосхемы в Wiki пользователь увидел буквальные `<center>` и `<left>` внутри условия и отсутствие логотипа в заголовке. Он сообщил версию PlantUML `1.2025.10`, Graphviz `14.0.1`, UTF-8 и лимит размера 4096. Локальная версия проекта — `1.2026.5`.

На официальном JAR `1.2025.10` внутри Docker воспроизведены буквальные теги. Их удаление из проверочной копии устранило дефект; `HorizontalAlignment center` остаётся в стиле условия. Пользователь впоследствии подтвердил: «правки в условии я уже проверил, теперь все отрисовывается корректно». Это приёмка варианта отображения, а не уже выполненная правка `components/condition.puml`.

Встроенный PNG на `1.2025.10` локально отображается в PNG и присутствует в SVG, в том числе при профилях `SANDBOX` и `INTERNET`. Скриншот диагностики пользователя показал: PNG и обычный спрайт исчезают и в заголовке, и в примечании; векторный SVG-спрайт отображается в обоих местах. Обычный спрайт превращается в растровую вставку; векторный — в `path`. По одному скриншоту нельзя установить, на каком этапе сервис или браузер исключает растровую вставку. Подтверждена пригодность простых векторных контуров в использованном способе вставки.

## Подготовленное решение

По запросу продолжить подготовлен отдельный прототип, не меняющий публичные компоненты. Знак преобразован из существующего `ruleway-icon.svg` в 134 залитых контура; обводки и переносы групп включены в геометрию. Градиент приближён 64 переходами цвета. Прототип остаётся векторным в SVG, не содержит `image`, `data:image`, внешних файлов или ссылок на SVG-эффекты. Размер — 48 × 48; исходный фирменный SVG не менялся.

Подготовлены воспроизводимые `generate_vector_logo.java` и `build_preview.py`. Они используют только имеющиеся JDK/Python в Docker и создают результаты вне исходников. Преобразователь защищён проверкой SHA-256 оригинала, поскольку поддерживает именно геометрию этого знака. Исходник для вставки содержит основной пример без дорожек с исправленным условием и новым знаком; данные шагов, ID и ссылки сохранены.

## Проверки

- Экспорт короткого образца и основного примера в SVG/PNG на `1.2025.10` и `1.2026.5`, без сети, репозиторий только для чтения. Версии JAR проверены.
- В коротком SVG 134 контура, в полном — 138; растровых вставок и буквальных тегов выравнивания нет. Размер полного SVG старого движка — 559 × 1422, нового — 573 × 1436.
- PNG обеих версий просмотрены. Локальное браузерное сравнение оригинала и векторной копии на размерах 48 и 256 пикселей, а также SVG схемы от `1.2025.10` подтвердило сохранение формы и читаемость знака. Переход цвета визуально сохраняется, математически это приближение исходного градиента.
- Публичные компоненты, существующий архив скилла и дизайн-ресурсы не менялись. Общие проверки завершённых компонентов не перезапускались; проверялись только копии для этой задачи.
- Повторная сборка из сохранённых исходников воспроизвела векторный ресурс; текст и адреса ссылок полного примера совпадают с вариантом без тегов. Проверены 83 локальные ссылки документации и `git diff --check`. Временный сервер предпросмотра остановлен после просмотра.

Временные результаты: `/tmp/ruleway_wiki_icon_20260922/`; воспроизводимая сборка — подкаталог `repro/`. Комплект для пользователя сохраняется в `dist/agent_skill/wiki_compatibility_preview/`, исключённом из Git существующим правилом. Это проверка оформления, не новый выпуск скилла.

## Приёмка и перенос в библиотеку

Пользователь подтвердил: «Формат логотипа принимается, в wiki он отобразился корректно» и поручил применить изменения к исходной базе и указать отдельные зависимости генерации кода для Wiki. Удалены `<center>`/`<left>` из `components/condition.puml`; в `components/assets/ruleway_logo.iuml` перенесён принятый векторный знак, вызов обновлён в `style.puml`. Публичный API не изменён. Защита `ruleway_logo_loaded` оставляет одно определение спрайта при подключении нескольких компонентов.

В скилл добавлены `config/export_profiles.tsv` и `references/yandex_wiki.md`. Цель `local` использует `1.2026.5`, цель `yandex-wiki` — `1.2025.10`, отдельный Docker-образ и файл `*_yandex_wiki.puml`; оба профиля задают `PLANTUML_LIMIT_SIZE=4096`. На стороне Wiki дополнительных локальных зависимостей нет: код полностью развёрнут. Общие контейнерные зависимости — Java 17, Python 3, DejaVu Sans и Graphviz из Dockerfile; версия Graphviz не имитирует весь сервер Wiki.

Оболочка выбирает образ до запуска; экспортёр проверяет версию текущего контейнера. Профиль Wiki отклоняет растровые вставки и буквальные теги, сохраняя исходник и не оставляя частичный комплект. Адреса, предметные данные, ID и маршруты не переписываются. Версия пакета повышена до `0.1.1-dev`.

- Все публичные примеры и проверочные схемы действия отрисованы в SVG/PNG на обеих версиях; проверены обязательные поля, пропуск необязательных, ссылки, запуск через stdin и перенос одной библиотеки вне репозитория. Ошибочные вызовы отклонены. Устаревшие ожидания PNG в JDK-проверке заменены проверками векторного знака.
- `tests/skill/check.py` выполнен для обеих целей: по девять схем, включая путь с кириллицей и специальными символами, контрольные суммы пакета, сохранение SLA/ссылок, самостоятельный рендер кода без `components/`, перенос комплекта, отказ перезаписи, ошибки без частичного результата. Основной пример с дорожками и многострочное условие просмотрены после переноса; ранее принятая форма знака сохранена.

Воспроизведение из корня проекта (каталоги результатов должны быть новыми):

```bash
docker build --tag rulewayuml-dev:plantuml-1.2025.10 \
  --build-arg PLANTUML_VERSION=1.2025.10 --file .devcontainer/Dockerfile .devcontainer

docker run --rm --network none --user vscode \
  --mount "type=bind,src=$PWD,dst=/workspace,readonly" \
  --entrypoint python3 rulewayuml-dev:plantuml-1.2025.10 \
  /workspace/tests/skill/check.py /tmp/wiki_checks yandex-wiki

bash dist/agent_skill/v0_1_1/rulewayuml/scripts/export.sh --target yandex-wiki \
  "$PWD/dist/agent_skill/v0_1_1/rulewayuml/assets" /tmp/wiki_demo \
  examples/basic_regulation_no_lanes.puml examples/review_regulation.puml \
  --asset examples/materials
```

Кликабельность внутри блока Wiki, загрузка SVG как изображения и поведенческие сценарии скилла остаются отдельными проверками. Приёмка оформления не выдаётся за их прохождение. Далее работа продолжается в задаче скилла.
